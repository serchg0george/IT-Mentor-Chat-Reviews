# Анализ проекта: Simulation

## Аргументы заказчика анализа

1. **Нереалистичная скорость освоения материала.** За 4.5 месяца освоены: многопоточность (`ReentrantLock`, `Condition`), алгоритм BFS, паттерны проектирования (Factory, Builder, Observer, Strategy), event-driven архитектура. Данный объём материала требует минимум 1-2 года систематического обучения.

2. **Несоответствие архитектурной сложности и качества продукта.** При использовании enterprise-паттернов и 8-уровневой структуре пакетов, базовый функционал (отрисовка спрайтов в консоли) не работает. Разработчик с реальным пониманием архитектуры проверил бы работоспособность приложения.

3. **Использование non-LTS версий Java.** В проекте указаны Java 22 и Java 24 — обе версии не являются LTS-релизами. Ни один профессиональный курс или ментор не рекомендует non-LTS версии для учебных проектов. LTS-версии (8, 11, 17, 21, 25) — стандарт индустрии. Это указывает на отсутствие систематического обучения.

4. **Невозможность воспроизведения.** При запросе воспроизвести проект в упрощённом виде (без паттернов, с трансляцией экрана) за несколько часов — автор, вероятно, не сможет этого сделать. Признаки маскировки AI-кода: удалённые комментарии, мелкие правки поверх сгенерированного кода.

5. **Применение алгоритмов и паттернов, нетипичных для начального уровня.** BFS с path reconstruction, паттерны Factory, Observer/EventBus, Strategy требуют глубокого понимания структур данных и ООП. Начинающий разработчик не применяет их без внешней помощи.

6. **Избыточная сложность без обоснования.** Для задачи симуляции достаточно: 2D-массив, игровой цикл, простой поиск. Реализовано: 8 пакетов, множественные Factory, EventBus, Layout system, Viewport. Объём коммитов (до 82 файлов за раз) указывает на генерацию кода блоками, а не итеративную разработку.

### Типичный паттерн AI-assisted разработки

1. **Человек** делает мелкие правки (fix, rename, небольшие feat)
2. **AI** генерирует большие блоки функциональности
3. **Человек** коммитит AI-код как свой
4. **Человек** потом правит баги, которые нашёл при тестировании

Это объясняет наличие и мелких fix-коммитов, и огромных "dumps".

### Что сделано для "человечности":
1. **Удалены комментарии** — AI обычно генерирует много комментариев
2. **Мелкие fix-коммиты** — создают иллюзию итеративной разработки

1. **Размеры коммитов** — невозможно скрыть

3. **Отсутствие TODO/FIXME** — AI не оставляет заметки себе
4. **Идеальные паттерны** — человек делает ошибки в применении
